## 0. 30 秒项目介绍（先背这个）

> 这是一个面向四路工业相机的 Qt6 视觉上位机，我独立做的。整体分采集、算法、显示、通信四层：采集层抽象了 Camera 接口，用工厂加单例管四路设备，实采走海康 MVS，也能切离线图片序列；显示层用容量 1 的有界队列加条件变量解耦采集和显示，主动丢帧保证延迟恒定；算法层封装 HALCON 的模板匹配和一维码识别，参数存 XML；另外还有 TCP 上报和日志模块。做这个项目最大的收获是解决了跨线程更新 UI 导致的偶发崩溃。

## 1. 采集层

**Q1：为什么抽象一个 Camera 基类？**
> 因为有两个数据源：海康相机和离线图片序列。业务代码不该关心具体实现，所以定义 `openCam/getFrame/sanpcap/stopCap` 这组接口，两个实现各自去做。上层只拿 `Camera*`，切换只改一个标志位。

**追问：基类为什么要虚析构？**
> 用 `Device*` 指针 delete 派生类对象时，如果析构不是虚函数，只会调用基类析构，派生类的成员（比如相机句柄）不会释放，属于未定义行为。

**Q2：为什么用工厂 + 单例？**
> 工厂让调用方不用 `#include "HK_Camera.h"`，只依赖接口，换品牌只改工厂一处；单例是因为设备表全局只有一张，必须唯一，否则两个管理器各管一份，释放会重复。

**追问：单例怎么保证线程安全？**
> 用局部静态：`static DeviceManager instance;`，C++11 起标准保证只初始化一次，且线程安全。同时删掉了拷贝构造和赋值，防止复制出第二个实例。

**Q3：设备表为什么用 `map<int, Device*>`？**
> 键是设备编号 1~4，值是指针。用编号而不是品牌，是因为同一个品牌可能有多台。

**追问：`getDevice` 为什么用 `find` 不用 `operator[]`？**
> `map::operator[]` 在键不存在时会**插入**一个默认值，也就是 `nullptr`。查询变成了修改，会把设备表污染，`size()` 也会变大。`find` 是只读的，找不到返回 `end()`。

**追问：`addDevice` 为什么用 `insert`？**
> `insert` 返回 `pair<迭代器, bool>`，从 `bool` 能知道是不是已经登记过；如果用 `m_mapDev[type] = dev`，键已存在时会**静默覆盖**，旧指针就丢了，没人 delete。

**Q4：四路相机怎么同时管理？**
> 构造时枚举一次，然后循环 4 次：工厂创建 → 按编号 1~4 登记 → 设备数够就建句柄。业务侧用 `phk_cam[i]` 保存指针直接调用。

**Q5：海康相机的采集流程？**
> 枚举设备 → `MV_CC_CreateHandle` 建句柄 → `MV_CC_OpenDevice` 打开 → GigE 相机用 `MV_CC_GetOptimalPacketSize` 设最佳包大小 → `MV_CC_GetImageBuffer` 取一帧 → 按像素格式转成 `cv::Mat`（RGB 要转 BGR）→ `MV_CC_FreeImageBuffer` 释放缓冲。

**追问：为什么转换时要 `clone()`？**
> SDK 的缓冲区在 `FreeImageBuffer` 之后就失效了。如果 `cv::Mat` 直接指向那块内存，就是悬垂指针，画面会花屏或崩。`clone()` 拷一份才安全。

**Q6：离线采集怎么模拟？**
> 目录里有 `picture_1.png` 到 `picture_N.png`，按序号循环读，读完回到 1。采集间隔 200ms 模拟 5fps。

**追问：为什么不用函数内的 `static int i`？**
> 那是函数内静态变量，四路相机会共用一个计数，图会错位。改成成员变量后每路各数各的。

## 2. 显示层

**Q7：采集和显示怎么解耦的？**
> 用容量 1 的有界队列加条件变量。采集线程 `pushFrame` 入队并 `notify`；工作线程在 `wait_for` 里等，被唤醒后取帧。

**Q8：为什么队列容量是 1？**
> 显示只关心**最新一帧**，旧帧没有价值。队列一长，延迟就会累积，内存也会涨。容量 1 意味着新帧覆盖旧帧——**主动丢帧**，保证延迟上限是一帧采集间隔，内存恒定。

**追问：丢帧会不会丢数据？**
> 显示会丢，但算法处理不丢——算法对每一帧都做识别。显示丢帧是设计取舍，不是缺陷。

**Q9：为什么用条件变量，不用 `sleep` 轮询？**
> 轮询有两个问题：没有数据时还在空转烧 CPU；新数据到达后最多要等一个轮询周期才处理。条件变量是“有事才醒”，零空转、响应立即。

**追问：什么是虚假唤醒？**
> 操作系统可能在没有 `notify` 的情况下唤醒等待线程。所以 `wait` 要带谓词，醒来先重新检查条件，不满足就继续睡。

**追问：100ms 超时是干什么的？**
> 兜底。正常靠 `notify` 唤醒，超时只防止通知丢失导致线程永远睡死。

**Q10：为什么用 `unique_lock` 而不是 `lock_guard`？**
> 条件变量的 `wait` 需要“释放锁 → 睡 → 重新加锁”，`lock_guard` 不支持中途解锁。

**Q11：为什么取到帧就立刻放锁？**
> 后面是识别，大概 30ms。如果握着锁做识别，采集线程 `pushFrame` 会被阻塞，采集节奏就被拖慢了。锁只保护共享数据（队列），越短越好。

**Q12：`notify` 为什么放在锁外面？**
> 如果在锁内通知，被唤醒的线程会立刻尝试抢同一把锁，抢不到又要睡，白白多一次上下文切换。

## 3. 线程安全

**Q13：为什么 UI 只能在主线程更新？**
> Qt 的控件不是线程安全的。子线程直接 `setPixmap`，轻则重绘错乱、闪屏，重则直接崩。这是未定义行为。

**Q14：你怎么更新的？**
> 统一走 `QMetaObject::invokeMethod(窗口, lambda, Qt::QueuedConnection)`，把“取控件、转格式、贴图”整段投递到主线程执行。全项目只有这一处调用 `setPixmap`。

**追问：`Queued` 和 `Direct` 区别？**
> `Direct` 在**调用者线程**立刻执行；`Queued` 把事件排进**接收者所在线程**的事件队列，异步执行。

**追问：`invokeMethod` 和信号槽有什么区别？**
> 本质一样，都是事件投递。区别是 `invokeMethod` 不用声明信号、可以直接带 lambda，但少了编译期的类型检查；信号槽能做一对多连接。

**Q15：这个崩溃你是怎么定位的？**
> 现象是四路同时跑偶尔崩，控制台没有报错。我先加了日志，发现崩之前最后一条是某个相机的识别结果，说明崩在显示那一段。然后做最小复现：单路连续跑不崩，四路一起必崩。定位到采集回调里直接调了 `setPixmap`。改成投递到主线程之后不再复现。

**Q16：线程怎么安全退出？**
> 分三步：置原子停止标志 → 唤醒（`notify_all`，socket 线程是 `closesocket`）→ `join` 等线程真正结束。

**追问：为什么不能 `detach`？**
> 线程函数里拿着 `this`，主窗口析构之后线程还在跑，访问成员就是野指针。`join` 保证对象销毁前线程已经结束。

**追问：为什么只置标志不够？**
> 阻塞在 `wait` 的线程不看内存，必须 `notify` 才会醒；阻塞在 `recv` 的线程卡在内核里，必须 `closesocket` 才能让它返回。

**追问：退出顺序为什么重要？**
> 先停显示（它还在往 UI 投递），再停采集（生产者），最后释放设备。如果先 `delete` 相机，采集线程还在用它，就是访问已释放内存。

**Q17：关闭时间从 5.2 秒降到 0.4 秒怎么做的？**
> 两个瓶颈：一是心跳线程 `Sleep(10000)`，`join` 要等满 10 秒；改成 50 次 200ms 的小步，每步检查退出标志。二是 socket 的 `recv` 阻塞，光置标志不醒，加了 `closesocket` 打断。采集循环的 200ms 节流也拆成 20ms 一步。

**追问：`atomic` 和 `mutex` 怎么选？**
> 单个标志位用 `atomic` 就够，无锁、开销小，保证可见性和原子性；多个字段要保持一致，就用 `mutex`。

## 4. 视觉算法

**Q18：形状模板匹配的流程？**
> ROI 框选 → 转灰度 → `CreateShapeModel` 建模板（金字塔层数、角度起止和步长、对比度、最小对比度）→ `FindShapeModel` 匹配（MinScore、NumMatches、MaxOverlap、亚像素、贪心度）→ 输出位置、角度、分数。

**追问：模板匹配的原理？**
> 基于边缘梯度。先提取模板的边缘点和方向，在目标图里按不同位置、角度、金字塔层搜索，算相似度，超过阈值就认为匹配。

**追问：金字塔层数的作用？**
> 层数多，高层先粗搜，速度快但精度低；层数少精度高但慢。`auto` 让 HALCON 根据模板自动选。

**追问：MinScore 调低会怎样？**
> 能匹配更弱的形状，但误匹配会增加。工业上一般 0.6~0.8。

**Q19：为什么参数要存 XML？**
> 现场调好的参数不能每次重调。启动读 XML、关闭回写，界面和配置双向同步。

**Q20：一维码识别的流程？**
> `CreateBarCodeModel` 建模型（它是参数容器，不需要图像）→ `SetBarCodeParam` 设码制、最小模块宽度、扫描线数、对比度阈值 → `FindBarCode` 返回区域和解码字符串。

**追问：为什么条码模型不需要图像？**
> 一维码是标准码制，编码规则是固定的，识别器只要参数就够；形状模板必须从图像里“学”样子。

**追问：哪个参数最影响识别率？**
> `element_size_min`（最小模块宽度）和对比度阈值。太小会把噪声当条码，太大会找不到细条码。

**Q21：为什么要旋转重试？**
> 条码可能竖贴或倒置。原图识别不到时，旋转 90/180/270 各试一次。

**追问：为什么不直接用 HALCON 的角度参数？**
> 试过 `orientation` 和 `orientation_tol`，对 90° 旋转无效。也试过 `RotateImage`，但它保持原尺寸，非正方形图一旋转就把条码边缘裁掉了，反而更读不出。最后用 OpenCV 的 `cv::rotate`（输出尺寸自适应），再转回 `HObject`。

**Q22：`cv::Mat` 和 `HObject` 怎么互转？**
> Mat → HObject：彩色图拆 BGR 三通道，逐行 `memcpy` 到连续缓冲（因为 `Mat` 每行可能有对齐填充），再 `GenImage3`，注意顺序是 R、G、B。HObject → Mat：`GetImagePointer1/3` 拿指针，逐行拷进 `Mat`。

**追问：为什么不能整块 `memcpy`？**
> `Mat` 的 `step`（每行字节数）不一定等于 `cols * 通道数`，可能有对齐填充，整块拷会错位。

## 5. 工程化

**Q23：日志模块怎么设计的？**
> 单例 + `QMutex` 保护文件写入 + 按天分文件 + 每行带毫秒时间戳和级别。界面显示用 `emit` 信号，接收者在主线程，自动排队。

**追问：为什么每行都 `flush`？**
> 日志最大的用途是崩溃后查原因。如果只在缓冲区里，崩溃时就没写盘，最需要的那几行反而丢了。牺牲性能换可靠性。

**追问：为什么在锁外发信号？**
> 如果槽函数里又调了日志，持锁发信号会自己等自己的锁，死锁。

**Q24：打包踩了什么坑？**
> 一开始直接打包 Debug 版，运行时报 0xC0000135——Debug 运行库不可分发。改用 Release 后还缺 DLL，用 `dumpbin /dependents` 递归分析，发现 MVS 的 `MvCameraControl.dll` 还依赖 GenICam 的 `GCBase`、`GenApi` 和 `MvRender`，把 MVS 运行时整个拷进去才行。

**Q25：中文路径踩过什么坑？**
> Qt6 的 `toStdString()` 返回 UTF-8，但 HALCON 和 Win32 API 在中文系统上要本地编码。路径直接用会报“文件不存在”，改成 `toLocal8Bit()` 才对。

**追问：还有别的编码问题吗？**
> 有。MVS 的头文件是 GBK，工程开了 `/utf-8`，编译时刷出几十万条 C4828 警告，加了 `/wd4828` 屏蔽。

## 6. 已知边界（主动说，显得清醒）

**Q26：这个项目有什么不足？**
> 三条：
> 1. **没真机验证**——MVS 链路按 SDK 文档实现，但没有产线设备，用离线序列和虚拟相机验证；
> 2. **识别吞吐**——四路共用一个工作线程，单帧约 30ms，真机 30fps 会跟不上，要拆线程池或降采样；
> 3. **日志没做大小切分**——按天分文件，单日可能很大，应该加 `maxSize` 滚动。

**Q27：如果重做一次，你会改什么？**
> 一是把识别按相机拆成线程池，或者做“每 N 帧识别一次”的降采样；二是日志改异步（写内存队列，单独线程落盘），避免高频日志拖慢调用线程；三是相机参数（曝光、增益）也配置化。

## 7. 可能被问的通用八股（针对简历关键词）

| 关键词 | 必答要点 |
|---|---|
| `RAII` | 构造获取资源、析构释放；异常安全；`lock_guard`、`unique_ptr` 都是 RAII |
| `智能指针` | `unique_ptr` 独占（删拷贝、留移动）；`shared_ptr` 引用计数原子但**对象本身不线程安全** |
| `移动语义` | 避免深拷贝；`std::move` 只是转成右值引用，真正转移在移动构造/赋值里 |
| `虚函数` | 对象里有 vptr 指向虚表，虚表存函数地址；虚析构用于基类指针删除派生类 |
| `STL` | `vector` 扩容 1.5~2 倍、`reserve` 预分配；`map` 红黑树 O(log n)，`unordered_map` 哈希平均 O(1) |
| `死锁` | 互斥、占有等待、不可抢占、循环等待；避免手段：固定加锁顺序、`scoped_lock`、超时 |
